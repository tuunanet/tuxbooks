TuxBooks 0.1.11 ships a native Arch package, makes the Automatic retry
toggle in Settings actually switch, and stops sync issues from staying
open after they have resolved themselves. The AppImage now runs on
stock Ubuntu and Debian without libfuse2, and the library sort menu
lists concrete orders that each place remembers.

## New

- **An Arch package.** TuxBooks installs on Arch and Manjaro from a native package: `sudo pacman -U ./tuxbooks-0.1.11-1-x86_64.pkg.tar.zst`. Its dependency list comes from the packaged binary rather than electron-builder's default (which mirrors Arch's system-linked electron package), and CI resolves the transaction inside a current `archlinux` container, so a dependency Arch drops fails the build instead of your install.
- **A concrete sort in every place.** The sort menu no longer offers a "Section order" placeholder; it lists Date added, Last read, Progress updated, Title, and Author, plus Added to collection inside a collection. Each place remembers its own choice and preselects its natural one: All Books and Recently Added open on Date added, Recently Read and Reading history on Last read, In Progress and Finished on Progress updated. While another sort is active, the menu marks the place's default.

## Changed

- **Sync issues are typed end to end.** One SyncIssueKind now carries a sync issue's kind from the database through the cascade boundaries, and the repeated resolve-and-title SQL lives in a single place. Internal cleanup only: no behavior change and no migration.

## Fixed

- The AppImage runs without FUSE 2. The portable build embeds AppImage's static type2-runtime, so `./tuxbooks-0.1.11.AppImage` starts on stock Ubuntu 22.04+ and Debian 12+ with no `libfuse2`/`libfuse2t64` install.
- The Automatic retry toggle in Settings > Sync works now. The switch added in 0.1.10 was dead on arrival: the renderer's call was missing from the IPC allowlist, so Electron rejected it and flipping it did nothing. It now turns the backoff sweep on or off for this device.
- Adopt failures close themselves. A `book_file_adopt_failed` issue now closes its own row when it resolves: the winning blob arrives intact, or the book's pointer moves on. No more rows staying open forever with the sidebar dot lit.
- A PDF page that leaves the view mid-zoom no longer errors. When a page's region vanished between commits, the reader attempted a 0x0 raster, tripped the engine guard, and waited for the next zoom to recover. The commitment now ends quietly and a returning page re-renders immediately.
- Copy diagnostics count progress conflicts. The support report's open-conflict count and sample dropped progress rows, the most frequent kind, so it understated the problem. Count and sample now share one clause and stay in lockstep; product surfaces still show no conflict count.
- Sync issue actions use the standard wire spelling. `openFolder` and `copyDetails` are camelCase everywhere now; both ends previously agreed on the wrong spelling, so nothing user-visible broke. The correction lands before anything depends on it.
- All 7 open Dependabot alerts (hono and `@hono/node-server`, reached only through the shadcn dev toolchain) are patched. Nothing users run ships them.

## Install on Ubuntu/Debian

```sh
sudo apt install ./tuxbooks_0.1.11_amd64.deb
```

## Install on Arch/Manjaro

```sh
sudo pacman -U ./tuxbooks-0.1.11-1-x86_64.pkg.tar.zst
```

## Portable AppImage

No `libfuse2` install is needed; the embedded runtime is statically linked.

```sh
chmod +x tuxbooks-0.1.11.AppImage
./tuxbooks-0.1.11.AppImage
```

On a system with no FUSE at all, run it with
`APPIMAGE_EXTRACT_AND_RUN=1`.

`SHA256SUMS.txt` verifies the downloads. The SBOM is published next to
the installers.

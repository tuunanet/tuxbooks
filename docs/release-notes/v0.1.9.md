TuxBooks 0.1.9 un-wedges sync after restore/forget cycles on large
histories. On the affected install, two books sat with sync issues whose
Retry could never succeed, and Reading history held one book that every
Forget run skipped, because a book record carried the database id 0.

## Fixed

- Restoring a book from a sync-replayed snapshot no longer creates the book record with database id 0. Snapshots rebuilt on the sync path default the id to 0 when the record is absent; restore now treats a non-positive id as "allocate a fresh one" instead of inserting rowid 0.
- A database migration re-ids any existing id-0 records to the next free id, so installs already carrying one heal on first start. Nothing else links to records by this internal id, so progress, annotations, and sync state stay attached.

With this release, the previously stuck sync issues resolve through their Retry action, and Forget selected covers every book in Reading history.

## Install on Ubuntu/Debian

```sh
sudo apt install ./tuxbooks_0.1.9_amd64.deb
```

Or run the portable AppImage:

```sh
chmod +x tuxbooks-0.1.9.AppImage
./tuxbooks-0.1.9.AppImage
```

`SHA256SUMS.txt` verifies the downloads. The SBOM is published next to
the installers.

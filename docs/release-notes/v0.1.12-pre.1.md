This pre-release fixes Locate File when the file it picks already belongs to
another library entry, so Select no longer closes with nothing happening. It
is a tester preview of 0.1.12; the stable release follows once this build has
been used.

## Fixed

- **Locate File resolves an owned file instead of refusing it.** Picking a file that another entry already owns used to fail with "that file is already in the library", and the app only logged the refusal. TuxBooks now looks at the duplicate before changing anything. An empty stale entry moves to Reading history and keeps its durable record; a stale entry whose bound content hash matches the picked bytes merges into the entry that owns the file, keeping every locator valid; and different bytes with reading state ask first. The detail panel and the library then offer three lossless choices: open the owner, move the stale entry to Reading history, or link it as a different edition without overwriting the owner's reading position.
- **An identity merge keeps provider and edition links.** A provider that both entries linked keeps the owner's link; queued provider progress follows only a link that moved; edition links to third books move to the surviving entry and self-links are dropped.
- **Locate File revives another file row of the same book.** Picking a second copy of the same durable book now marks that row available instead of reporting a reconnect that changed nothing.

## Install on Ubuntu/Debian

```sh
sudo apt install ./tuxbooks_0.1.12-pre.1_amd64.deb
```

## Install on Arch/Manjaro

```sh
sudo pacman -U ./tuxbooks-0.1.12-pre.1-1-x86_64.pkg.tar.zst
```

## Portable AppImage

No `libfuse2` install is needed; the embedded runtime is statically linked.

```sh
chmod +x tuxbooks-0.1.12-pre.1.AppImage
./tuxbooks-0.1.12-pre.1.AppImage
```

On a system with no FUSE at all, run it with
`APPIMAGE_EXTRACT_AND_RUN=1`.

`SHA256SUMS.txt` verifies the downloads. The SBOM is published next to
the installers.

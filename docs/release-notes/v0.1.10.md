TuxBooks 0.1.10 turns sync into a background system that settles by
itself. Races resolve to a pre-decided winner instead of a review queue,
failed work retries on a schedule, and an edited book file now reaches
every device as a shared version, so the library converges on the same
bytes while annotations and reading progress stay attached.

## New

- **Book files follow the library.** Re-importing an edited book, whether from Calibre, Sigil, or by replacing the file, publishes its bytes to the sync folder. Other devices adopt the newest version when the book is closed; while it is open, the library marks it **Newer version** and waits until you close it. Annotations and progress stay on the same book across the swap.
- **Automatic retry.** Sync issues that have a Retry action now retry on a backoff schedule: 1 minute, 5 minutes, 15 minutes, 1 hour, 6 hours, then daily, up to five attempts (three for book lifecycle replay). Hash failures keep their existing backfill loop. The on-by-default **Automatic retry** switch in Settings > Sync turns the sweep off for this device. Settings and the sidebar report only problems the machine gave up on or that need a person, so recoverable work no longer competes for attention.
- **Sync folder watching.** The engine watches the sync folder and wakes as soon as another device publishes work, instead of waiting for its periodic pass.
- **A larger Settings window.** Settings scales with the app window up to a bounded size and stays on screen when the window is maximized, dragged to a corner, or restored.

## Changed

- **No more conflict review.** Every race has a pre-decided winner: the newer write wins per field, and a delete beats a concurrent edit. The losing value is kept in diagnostics for support but never asks you to choose, and the Conflicts review surface is gone.
- **Edit clocks are stamped when you write.** An edit made offline no longer gets a reconnect-time timestamp that could outrank newer work from another device.
- **Bounded staging storage.** The current version of every re-imported book stays in the sync folder so a device that lost its file can always fetch it again; superseded versions are pruned after 90 days. A book over the 256 MiB blob cap reports an issue naming the file.

## Fixed

- Forget and restore now remove the stale library card they leave behind instead of showing the same book twice until a reload.
- A library-mismatch error offers **Reconnect** in Settings > Sync, opening the usual Use this library / Start a new library choice without disconnecting first.
- **Copy diagnostics** and sync issue details now reach the system clipboard through the main process instead of being blocked by the renderer's clipboard policy.
- A failed capture no longer publishes a second operation file for the same write, so the sync folder keeps one operation per change.
- The adopt sweep no longer writes a book's sync uid to stderr when an adoption fails; it names the local book id instead.

## Install on Ubuntu/Debian

```sh
sudo apt install ./tuxbooks_0.1.10_amd64.deb
```

Or run the portable AppImage:

```sh
chmod +x tuxbooks-0.1.10.AppImage
./tuxbooks-0.1.10.AppImage
```

`SHA256SUMS.txt` verifies the downloads. The SBOM is published next to
the installers.
